## Обзор интерфейса

IvkExportTool имеет четыре окна:

### Стартовое окно (Start Window)

Первое окно, которое вы видите при запуске. Содержит:

- **Кнопка "Ручная настройка подключения"**: Открывает окно с полями для ввода данных подключения
- **Кнопка "Автоподключение"**: Автоматически перебирает предустановленные учётные данные

### Окно ручного подключения (Connection Window)

Окно для ручной настройки подключения к БД. Содержит:

- **Поля ввода**: Хост, Порт, Логин, Пароль
- **Кнопки**: "Тест подключения", "Подключиться"
- **Кнопка возврата**: Возврат на стартовое окно (слева от крестика)
- **Индикатор статуса**: Отображает результат подключения

### Окно автоподключения (Auto Connection Window)

Окно для автоматического подключения к БД ИВК. Содержит:

- **Поля ввода**: Хост, Порт (загружаются из настроек)
- **Кнопки**: "Отмена" (активна во время перебора), "Автоподключение"
- **Кнопка возврата**: Возврат на стартовое окно (слева от крестика)
- **Индикатор статуса**: Отображает прогресс "Попытка N из M..."

### Главное окно (Main Window)

Отображается после успешного подключения. Содержит:

- **Панель управления**:
  - Выпадающий список баз данных
  - Кнопка "Сменить подключение"
  - Информация о текущем подключении

- **Панель фильтрации и поиска**:
  - Поле поиска таблиц
  - Счётчик таблиц (выбрано/всего)

- **Таблица данных**:
  - Столбцы: Чекбокс, Имя, Строки, Размер, Движок
  - Сортировка по клику на заголовок
  - Тристейтный чекбокс в заголовке для массового выбора

- **Панель действий**:
  - Кнопка "Экспортировать"
  - Кнопки "Выбрать все" / "Снять выбор"

## Подключение к базе данных

При запуске приложения открывается стартовое окно с выбором способа подключения.

### Способ 1: Автоподключение (рекомендуется для ИВК)

Автоподключение автоматически перебирает предустановленные учётные данные для подключения к БД ИВК.

1. **Запустите приложение** — откроется стартовое окно
2. **Нажмите "Автоподключение"**
3. **Введите параметры сервера**:

   | Поле | Описание | Пример |
   |------|----------|--------|
   | **Хост** | IP-адрес или доменное имя сервера | `192.168.1.100` |
   | **Порт** | Порт MySQL сервера | `3306` (по умолчанию) |

4. **Нажмите "Автоподключение"**:
   - Приложение начнёт перебор учётных данных
   - Статус: "Попытка 1 из 7...", "Попытка 2 из 7..." и т.д.
   - Таймаут: 5 секунд на каждую попытку
   - **Отмена**: Нажмите кнопку "Отмена" для прерывания

5. **Результат**:
   - ✅ **Успешно**: Откроется главное окно
   - ❌ **Не удалось**: "Не удалось подключиться ни с одной учётной записью"

### Способ 2: Ручное подключение

Используйте для подключения к любому MySQL серверу с известными учётными данными.

1. **Запустите приложение** — откроется стартовое окно
2. **Нажмите "Ручная настройка подключения"**
3. **Заполните поля**:

   | Поле | Описание | Пример |
   |------|----------|--------|
   | **Хост** | IP-адрес или доменное имя сервера | `localhost`, `192.168.1.100`, `mysql.example.com` |
   | **Порт** | Порт MySQL сервера | `3306` (по умолчанию) |
   | **Логин** | Имя пользователя MySQL | `root`, `myuser` |
   | **Пароль** | Пароль пользователя | `********` |

4. **Тест подключения** (необязательно):
   - Нажмите кнопку **"Тест подключения"**
   - Дождитесь результата:
     - ✅ **Успешно**: "Подключение успешно"
     - ❌ **Ошибка**: Отобразится сообщение с описанием проблемы

5. **Подключиться**:
   - Нажмите кнопку **"Подключиться"**
   - При успехе откроется главное окно

### Сохранение параметров подключения

Приложение автоматически сохраняет последние использованные параметры подключения:

- **Windows**: `%APPDATA%\IvkExportTool\settings.json`
- **Linux/macOS**: `~/.config/IvkExportTool/settings.json`

```json
{
  "Connection": {
    "Host": "192.168.1.100",
    "Port": 3306,
    "Username": "admin",
    "EncryptedPassword": "base64..."
  },
  "LastExportDirectory": "/path/to/exports"
}
```

> **Примечание**: Пароль сохраняется в зашифрованном виде. Зашифрованный пароль с Windows НЕ совместим с Linux и наоборот.

### Смена подключения

Если вам нужно подключиться к другому серверу:

1. В главном окне нажмите кнопку **"Сменить подключение"**
2. Главное окно закроется
3. Откроется **стартовое окно** с выбором способа подключения
4. Выберите ручное или автоподключение

> **Примечание**: Окно откроется на том же мониторе и примерно в той же позиции, где было главное окно.

## Работа с таблицами

### Выбор базы данных

После подключения к серверу:

1. Откройте выпадающий список **"База данных"**
2. Выберите нужную базу данных
3. Приложение автоматически загрузит список таблиц

### Просмотр информации о таблицах

Таблица отображает следующую информацию:

| Столбец | Описание |
|---------|----------|
| **☑** | Чекбокс для выбора таблицы |
| **Имя** | Название таблицы |
| **Строки** | Количество строк в таблице |
| **Размер** | Размер таблицы (в B, KB, MB, GB) |
| **Движок** | Тип движка (InnoDB, MyISAM, и т.д.) |

### Сортировка таблиц

Кликните на заголовок столбца для сортировки:

- **Первый клик**: Сортировка по возрастанию (A→Z, 0→9)
- **Второй клик**: Сортировка по убыванию (Z→A, 9→0)
- **Третий клик**: Сброс сортировки

### Поиск таблиц

Используйте поле поиска для быстрой фильтрации:

1. Введите часть имени таблицы в поле **"Поиск..."**
2. Список автоматически отфильтруется
3. Поиск работает без учёта регистра (case-insensitive)

**Примеры**:
- `user` → найдёт `users`, `user_profile`, `admin_users`
- `log` → найдёт `logs`, `error_log`, `login_history`

### Выбор таблиц для экспорта

#### Выбор отдельных таблиц

Кликните на чекбокс напротив нужной таблицы.

#### Массовый выбор

**Способ 1**: Кнопки управления
- **"Выбрать все"** — выбрать все таблицы (с учётом фильтра)
- **"Снять выбор"** — снять выбор со всех таблиц

**Способ 2**: Чекбокс в заголовке таблицы
- **☐** (пусто) → **☑** (выбрать все)
- **☑** (все выбраны) → **☐** (снять выбор)
- **⊟** (частичный выбор) → **☑** (выбрать все)

### Счётчик выбранных таблиц

Над таблицей отображается информация:

```
Выбрано: 5 из 23 таблиц
```

## Экспорт данных

### Процесс экспорта

1. **Выберите таблицы** для экспорта (минимум одна)

2. **Нажмите кнопку "Экспортировать"**

3. **Выберите место сохранения**:
   - Откроется стандартный диалог сохранения файла
   - Предлагаемое имя файла:
     - **Одна таблица**: `database_tablename_20250120_153045.sql`
     - **Несколько таблиц**: `database_20250120_153045.sql`
   - Выберите папку и при необходимости измените имя
   - Нажмите **"Сохранить"**

4. **Дождитесь завершения экспорта**:
   - Отобразится индикатор прогресса (для больших таблиц)
   - По завершении появится уведомление об успехе

### Формат экспортированного файла

Экспортированный SQL-файл содержит:

```sql
-- IvkExportTool Export
-- Database: mydb
-- Date: 2025-01-20 15:30:45
-- Tables: users, orders

SET NAMES utf8mb4;
SET FOREIGN_KEY_CHECKS = 0;

-- ----------------------------
-- Table structure for users
-- ----------------------------
DROP TABLE IF EXISTS `users`;
CREATE TABLE `users` (
  `id` int NOT NULL AUTO_INCREMENT,
  `username` varchar(255) NOT NULL,
  `email` varchar(255) NOT NULL,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ----------------------------
-- Records of users
-- ----------------------------
BEGIN;
INSERT INTO `users` VALUES (1, 'john_doe', 'john@example.com');
INSERT INTO `users` VALUES (2, 'jane_smith', 'jane@example.com');
COMMIT;

SET FOREIGN_KEY_CHECKS = 1;
```

### Особенности экспорта

- ✅ **Полная структура**: Включает все индексы, ключи, constraints
- ✅ **Все данные**: Экспортируются все строки таблицы
- ✅ **UTF-8 поддержка**: Корректная работа с кириллицей и спецсимволами
- ✅ **Транзакции**: Используются BEGIN/COMMIT для целостности данных
- ✅ **DROP IF EXISTS**: Безопасное пересоздание таблиц при импорте

### Ограничения

- ⚠️ **Размер файла**: Большие таблицы (>1 GB) могут создавать очень большие SQL-файлы
- ⚠️ **Память**: Экспорт выполняется потоково, но для очень больших таблиц требуется достаточно RAM
- ⚠️ **Время**: Экспорт миллионов строк может занять несколько минут

> **Совет**: Для очень больших таблиц рассмотрите экспорт частями или используйте альтернативные инструменты (mysqldump).

### Настройки экспорта

Последняя использованная папка сохраняется в настройках:

```json
{
  "LastExportDirectory": "C:\\Users\\username\\exports"
}
```

При следующем экспорте диалог откроется в этой папке.

## Импорт экспортированных данных

### Через MySQL CLI

```bash
mysql -u username -p database_name < exported_file.sql
```

**Пример**:

```bash
mysql -u root -p mydb < mydb_20250120_153045.sql
```

### Через MySQL Workbench

1. Откройте MySQL Workbench
2. Подключитесь к серверу
3. Выберите базу данных
4. **File → Run SQL Script...**
5. Выберите экспортированный файл
6. Нажмите **"Run"**

### Через phpMyAdmin

1. Откройте phpMyAdmin
2. Выберите базу данных
3. Перейдите на вкладку **"Импорт"**
4. Нажмите **"Выберите файл"** и укажите SQL-файл
5. Нажмите **"Вперёд"**

### Восстановление с заменой данных

Экспортированный файл содержит `DROP TABLE IF EXISTS`, поэтому:

- ✅ Существующие таблицы будут удалены
- ✅ Таблицы будут созданы заново
- ✅ Данные будут вставлены

> **Внимание**: Это удалит существующие данные в таблицах!

## Лучшие практики

### Безопасность

- 🔒 **Не храните пароли**: Удаляйте `settings.json` на общих компьютерах
- 🔒 **Используйте read-only пользователей**: Создайте пользователя с правами только на чтение

```sql
CREATE USER 'readonly'@'%' IDENTIFIED BY 'password';
GRANT SELECT ON *.* TO 'readonly'@'%';
FLUSH PRIVILEGES;
```

### Производительность

- ⚡ **Экспортируйте в нерабочее время**: Для больших БД экспорт может нагружать сервер
- ⚡ **Используйте фильтрацию**: Экспортируйте только нужные таблицы
- ⚡ **Сжимайте файлы**: После экспорта архивируйте SQL-файлы (gzip, 7z)

### Резервное копирование

- 💾 **Регулярные бэкапы**: Настройте автоматический экспорт (через cron/Task Scheduler)
- 💾 **Проверяйте экспорты**: Периодически тестируйте восстановление из бэкапов
- 💾 **Храните версии**: Не удаляйте старые экспорты сразу

### Организация файлов

## FAQ

### Можно ли экспортировать в другие форматы (CSV, JSON)?

В текущей версии поддерживается только SQL формат. Поддержка CSV и JSON планируется в будущих версиях.

### Как экспортировать только структуру без данных?

В текущей версии эта опция недоступна. Используйте mysqldump:

```bash
mysqldump -u username -p --no-data database_name > structure_only.sql
```

### Поддерживается ли экспорт представлений (views)?

Нет, в текущей версии экспортируются только таблицы. Поддержка views планируется.

### Можно ли экспортировать триггеры и процедуры?

Нет, экспортируются только таблицы и их данные.

### Какой максимальный размер таблицы можно экспортировать?

Теоретически нет ограничений, но практически:
- **< 1 GB**: Отлично работает
- **1-10 GB**: Может потребовать времени
- **> 10 GB**: Рекомендуется использовать mysqldump

### Как автоматизировать экспорт?

В текущей версии нет CLI интерфейса. Для автоматизации используйте mysqldump:

```bash
#!/bin/bash
mysqldump -u root -p password database_name > backup_$(date +%Y%m%d).sql
```

## Устранение неполадок

### Экспорт зависает на больших таблицах

**Причина**: Большой объём данных

**Решение**:
- Дождитесь завершения (может занять несколько минут)
- Экспортируйте таблицы по отдельности
- Увеличьте timeout подключения

### Ошибка "Lost connection to MySQL server"

**Причина**: Timeout подключения при экспорте больших данных

**Решение**:
1. Увеличьте `max_allowed_packet` в MySQL:

```sql
SET GLOBAL max_allowed_packet=1073741824; -- 1 GB
```

2. Увеличьте timeout:

```sql
SET GLOBAL wait_timeout=600;
SET GLOBAL interactive_timeout=600;
```

### Кириллица отображается некорректно

**Причина**: Проблема с кодировкой

**Решение**:
- Убедитесь, что БД использует UTF-8
- Откройте SQL-файл в редакторе с поддержкой UTF-8
- При импорте укажите `--default-character-set=utf8mb4`

```bash
mysql -u root -p --default-character-set=utf8mb4 mydb < export.sql
```

### Не хватает прав доступа

**Ошибка**: "Access denied for user 'username'@'host' to database 'dbname'"

**Решение**: Предоставьте необходимые права:

```sql
GRANT SELECT ON database_name.* TO 'username'@'%';
FLUSH PRIVILEGES;
```

### Экспорт создаёт пустой файл

**Причина**: Таблицы пустые или нет прав на чтение данных

**Решение**:
- Проверьте, что таблицы содержат данные
- Убедитесь, что пользователь имеет права SELECT
